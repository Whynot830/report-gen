# reportgen

Генератор отчётов по практическим работам (docx, ГОСТ-оформление) из Python-пейлоадов. Титульный лист копируется из шаблона коллеги, дальше собираются содержание, заголовки, таблицы, рисунки и список литературы.

Пейлоады и рисунки конкретных работ живут только локально: в репозитории остаётся общая логика сборки.

## Установка

Клонируйте репозиторий **внутрь папки семестра** (рядом с папками дисциплин), чтобы относительные пути к шаблонам и готовым отчётам совпали:

```bash
cd ~/Desktop/uni/3sem
git clone https://origin.cursor.com/why-not-dev/reportgen.git reportgen
python3 -m pip install -r reportgen/requirements.txt
```

Нужен Python 3.11+ и готовый `.docx`-шаблон с титульным листом (до строки «Москва 2026»). Стили тела (заголовки, подписи, списки) всегда берутся из вшитого `reportgen/assets/gost_styles.docx`; к Heading 2/3 генератор добавляет автонумерацию. Поля страницы: верх/низ 2 см, слева 3 см, справа 1,5 см; колонтитулы 1 см.

## Запуск

Из корня семестра:

```bash
python3 -m reportgen --help
python3 -m reportgen <имя>
python3 -m reportgen <имя-1> <имя-2>
python3 -m reportgen all
```

После сборки в Word: правый щелчок по содержанию → **Обновить поле**.

## Пейлоады

Файлы в `payloads/` (кроме `__init__.py` и референса `example.py`) в git не попадают. Модуль `foo_bar.py` с объектом `PAYLOAD` сам регистрируется как `foo-bar`.

Новый отчёт: скопируйте `payloads/example.py`, укажите в `meta` пути к шаблону и выходному файлу. Дополнительные имена — через `ALIASES` в модуле или `meta.aliases`.

Рисунки и вспомогательные скрипты кладите в `reportgen/assets/<дисциплина>/` — эта папка тоже локальная.

Скриншоты терминала (Ghostty): модуль `reportgen.terminal`.

```bash
python3 -m reportgen.terminal --title /Users/whynot -o shot.png <<'EOF'
whynot@MBP14 ~ % ls
EOF
```
